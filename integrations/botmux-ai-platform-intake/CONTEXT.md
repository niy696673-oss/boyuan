# 机器人渠道接入上下文

这个上下文承接飞书、企业微信智能机器人与微信客服中的 BP 文件消息，以及明确的公司研究指令，并把可重试的接收事实交给博源 AI 平台。

## 语言

**渠道对话会话（Channel Conversation Session）**：
同一飞书聊天与发送人持续复用的 OpenCode session；文字、BP 原文与结果都属于此会话的上下文。会话 ID 与收件队列持久化，重启后可恢复；它与每份材料的平台分析 conversation 分开，不能用单条消息 ID 代替。
_Avoid_: 每条消息新建的模型会话、跨用户共享历史

**对话收件队列（Conversation Inbox）**：
同一渠道对话内文字与文件共用的先进先出序列；上一条处理、投递及有限重试结束后才处理下一条。不同对话独立推进，失败终止后不阻塞后续消息。
_Avoid_: 仅文件内部去重、先收后问但先答后分析

**接入任务（Intake Job）**：
一次从渠道消息获取文件或公司研究指令并交给平台的可重试工作记录。
_Avoid_: 分析任务、材料任务

**快速回执（Fast Acknowledgement）**：
只表示材料已收到或明确拒绝的受理结果，不包含模型提取字段。
_Avoid_: 分析结果、研究报告

**快速完成卡（Fast Completion Card）**：
深度分析完成前，由快速模型从材料中提取少量字段形成的渠道结果；飞书使用卡片，企业微信智能机器人与微信客服使用普通文本。它是临时摘要，不是深度分析结果。
_Avoid_: 快速回执、深度分析报告

**状态卡（Status Card）**：
飞书收到文件后立即创建的唯一机器人回复。初始内容表示处理中；Luna 完成或接入失败后，系统更新同一条卡片消息，不追加第二条回复。
_Avoid_: 新增完成回复、Sol 状态卡

**状态流（Status Stream）**：
企业微信智能机器人收到文件或公司命令后立即创建的流式文本回复。初始内容表示处理中；快速分析完成或接入失败后，以相同 stream id 结束这条回复。
_Avoid_: 独立完成消息、中间模型说明

**微信客服消息序列（WeChat Customer Service Message Sequence）**：
普通微信用户把 PDF 转发给微信客服后收到的有限普通文本序列。微信客服 API 不支持更新已发消息，因此先发送一条处理中消息，再发送快速结果；快速结果超过单条 2048 字节限制时最多拆成三条。不得发送中间模型说明。同一同步窗口中已经撤回的文件不进入分析，多文件按顺序处理，回复额度耗尽时不推进游标。渠道适配器使用独立的 `wechat-kf` 回执与游标命名空间；在工作台增加独立筛选项前，平台来源字段暂复用 `wecom`，不得据此套用状态流的 stream-id 契约。
_Avoid_: 交互卡片、状态流、每次回调重复回复

**平台回链（Platform Link）**：
指向博源工作台中深度分析对话，或指向已有公司网络／行业产业链的可访问链接。快速完成卡只查询已有实体；未匹配到实体时回到深度分析对话，不在快速链路建档。
_Avoid_: 原文件链接、飞书消息链接、快速卡新建实体

**公司快速研究（Company Quick Research）**：
Luna 基于平台正式知识、已有材料摘要和本次持久化公开检索快照生成的公司摘要。它与工作台 Sol 深度研究并行，复用同一检索快照，但不生成正式知识或产业链关系。
_Avoid_: BP 事实核验、深度研究报告、自动建档

**主体状态（Identity State）**：
公司研究入口对主体匹配的显式结果：已有正式主体、新建待确认主体或歧义待确认。歧义状态不得猜测主体，也不得启动公开检索或 Luna 提取。
_Avoid_: 隐式选择、模糊匹配成功

## 共用业务与渠道边界

飞书与微信客服的 `channel-conversation` 负责自然意图、持久 session、历史与 BP 上下文、同一用户 FIFO、有限重试；`conversation-workflows` 统一调用 BP/公司分析及受控材料上下文 API。两者只适配消息、文件下载和结果投递。渠道命名空间隔离用户，不能因显示姓名相同自动合并跨渠道身份。

微信客服用客服账号与 external_userid 生成 owner，输入消息持久化后即可继续拉取；发件箱持久化已送页数与固定 msgid。公司研究一条输入只发一条受理通知，合并结果最多三页（每页2048字节），超过容量明确提示省略，允许继续追问。不输出内部工作台链接。既有图片名单识别仍使用专门图片适配器，不属于本次文字/PDF 会话上下文。

## 通约助手身份与业务范围

机器人对外名称为“通约助手”。消息模板与模型身份使用此名；原始材料、公司/机构名称和来源引用保持原样，技术路径、应用ID与历史审计记录不作品牌替换。

自然对话先按语义与当前上下文判断业务范围：公司/行业研究、BP与项目资料、投融资、尽调、风险和基金匹配，以及这些资料的翻译/摘要/计算与使用帮助。无关任务不因含公司名或声称用于投资而放行；旧会话、上传材料和用户角色指令也不能扩大范围。无关请求的模型协议仅允许 `out_of_scope`，适配器转成统一简短引导，不携带生成答案、不进入研究工作流。混合请求只处理清楚的业务部分；转回业务后正常继续。文件入口仍只执行既有企业材料提取，不执行文件内指令。
