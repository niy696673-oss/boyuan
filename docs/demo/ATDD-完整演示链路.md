> 版本：v1.0

> 目标：验证“材料上传 → 智能分析 → 知识确认 → 知识沉淀 → 关联洞察”的目标完整链路。

## 1. 验收结论口径

本文件描述目标完整链路，不把模拟能力表述为正式能力。每个步骤使用以下状态：

- `PASS`：已在当前本地平台用真实输入和可观察证据验证。
- `PARTIAL`：主路径可用，但仍有渠道、数据或交互缺口。
- `BLOCKED`：目标链路要求存在，但当前系统尚未实现或未配置。
- `NOT RUN`：能力已具备，但本轮尚未执行。

整场演示只有在所有 `P0` 场景均为 `PASS` 时才能宣布完整通过。任何 `BLOCKED` 必须在开场前明确告知观众，不得用后台手工写库或口播掩盖。

## 5. 讲解员逐步操作与预期结果

### Step 0 - 开场说明

**操作**

1. 告知观众本次展示目标完整链路。
2. 明确说明飞书适配器仍是阻塞项，因此飞书前三步只展示目标交互标准；实际分析从网页端上传同一份 BP 继续。
3. 打开平台工作台，确认顶部“待确认”数量可见。

**预期结果**

- 观众能区分“目标交互”和“当前已接通能力”。
- 不把网页上传冒充为飞书接入。

**验收证据**

- 平台首页截图。
- 本文第 4 节阻塞项。

### Step 1 - 飞书输入公司名称（目标交互）

**演示输入**

`研究苏州兆鑫驰智能科技有限公司，重点关注产业链位置、客户、投资机构和竞争关系。`

**目标操作**

1. 在飞书机器人对话中发送公司名称和研究意图。
2. 等待机器人返回接收回执和初步公司卡片。

**预期结果**

- 5 秒内返回“已接收”回执。
- 卡片展示标准名称、已有材料数、已有正式知识数、主体匹配状态和“进入平台”深链。
- 同名或别名不唯一时必须要求人工选主体，不得静默合并。

**当前状态**：`BLOCKED`

**失败处理**

- 无飞书适配器时停止该步骤，切换网页工作台输入同一研究意图，并明确这是替代路径。

### Step 2 - 飞书上传公司 BP（目标交互，网页端实跑）

**操作**

1. 上传 `苏州兆鑫驰BP.pdf`。
2. 观察接收回执。
3. 在网页工作台上传同一文件，作为当前可执行路径。

**预期结果**

- 文件被安全归档并计算 SHA-256。
- 重复文件显示“复用原材料”，但允许创建新的分析任务，不重复存储文件。
- 最近对话新增“苏州兆鑫驰BP.pdf”任务。
- 任务依次完成存储校验、解析、分类、主体识别、深度分析、候选生成。
- 任务记录显示 `openai / gpt-5.6-sol / high`。
- 工具记录包含 `skill` 和 `sequential-thinking_sequentialthinking`。

**渠道状态**：飞书 `BLOCKED`；网页端 `PASS` 或 `NOT RUN`（以本轮记录为准）。

**失败处理**

- 解析失败：保留失败原因，不生成正式知识。
- 模型失败：任务显示失败，不允许回退到确定性演示模型。
- 主体不唯一：进入主体待确认，不继续自动沉淀。

### Step 3 - 飞书上传公司名单图片（目标交互）

**操作**

1. 上传 `第十一届创客中国四川赛区企业榜单.jpg`。
2. 系统执行 OCR，并识别榜单中的企业名称、项目名称、名次和成绩。

**预期结果**

- 返回识别总数、已存在主体、新建主体、疑似同名、识别失败数量。
- 每一行保留图片来源和 OCR 证据区域。
- 低置信度名称必须进入人工确认。
- 榜单公司不会被错误合并到苏州兆鑫驰。

**当前状态**：`BLOCKED`

**阻塞原因**

- 飞书附件接收未接入。
- 图片 OCR 尚未接入公司名单处理运行时。
- 当前公司名单落地页仅支持 CSV。

### Step 4 - 在最近对话查看深度分析

**操作**

1. 进入平台首页。
2. 在“最近对话”选择苏州兆鑫驰 BP 任务。
3. 展开任务步骤、13 个分析章节和候选知识。

**预期结果**

- 对话标题、文件名、公司主体和任务状态一致。
- 13 个 BP 章节按固定顺序展示。
- 每条事实候选至少有一个 BP 证据块和页码。
- 投资、合作、上游、下游、竞争关系以候选形式出现。
- 没有材料依据的章节明确显示“材料未披露”或“证据不足”。

**验收证据**

- 最近对话任务截图。
- 任务 provider、model、variant、toolUsage 记录。
- 章节数和候选数记录。

### Step 5 - 在待确认中心确认研究知识

**操作**

1. 点击“处理待确认”。
2. 逐条核对陈述、BP 引文和页码。
3. 对正确事实点击“确认”。
4. 对文字不准确但证据成立的内容执行“修改并确认”。
5. 对证据不足或关系方向错误的内容点击“驳回”。

**预期结果**

- 确认操作要求候选版本一致。
- 确认后候选变为已确认，并生成正式知识版本。
- 修改确认同时保存修改前后内容。
- 驳回不生成正式知识。
- 所有操作写入审计记录。

**关系硬门槛**

| 关系类型 | 最低要求 | 允许的证据 |
| --- | --- | --- |
| 投资 | 至少 1 个明确投资机构 | BP 页码或公开投资公告 URL |
| 合作 | 至少 1 家明确合作/客户企业 | BP 页码或双方公开合作 URL |
| 上游 | 优先使用明确供应商；若只能证明具名企业处于该业务上游，必须标注“产业链推断、非直接采购” | BP 页码或上游企业官网/供应关系公开 URL |
| 下游 | 至少 1 家明确客户/应用企业 | BP 页码或客户案例公开 URL |
| 竞争 | 至少 1 家 BP 明确点名的竞品企业 | BP 竞争分析页码 |

任何一类没有证据化企业主体，本轮完整链路均判定不通过。

### Step 6 - 验证知识沉淀和公司关联

**操作**

1. 打开“公司”页面。
2. 搜索“苏州兆鑫驰”。
3. 打开公司卡片和详情页。
4. 查看材料、已确认知识和待确认数量。

**预期结果**

- 公司只有一个标准主体，简称作为别名存在。
- BP 显示在最近材料中。
- 已确认知识数量增加，待确认数量相应减少。
- 每条正式知识能够回溯到原候选和 BP 证据。
- 页面刷新和服务重启后数据仍存在。

### Step 7 - 验证行业和产业链位置

**操作**

1. 在公司详情打开“产业关系”。
2. 打开对应行业页面。
3. 查看公司所在产业链节点。

**预期结果**

- 行业归属来自已确认知识或已确认位置，不使用未确认推断冒充。
- 苏州兆鑫驰在 MIM/精密制造相关产业链节点可见。
- 上游材料与设备、公司自身能力、下游消费电子/汽车等位置方向正确。
- 候选位置使用虚线或“待确认”标识；确认位置使用实线。

### Step 8 - 验证五类企业关系

**操作**

1. 在公司详情查看企业关系区域。
2. 分别切换投资、合作、上游、下游、竞争。
3. 点击关系企业，检查关系方向、状态和证据。

**预期结果**

- 五类关系均至少出现 1 条已确认记录。
- 每条关系展示对方标准公司名称和关系类型。
- 每条关系可定位到 BP 页码或公开网页 URL。
- 已确认关系使用实线；未确认建议使用虚线。
- 竞争关系不显示为合作或上下游关系。
- 投资方向为“投资机构 → 苏州兆鑫驰”。
- 供应方向为“上游供应商 → 苏州兆鑫驰”。
- 客户方向为“苏州兆鑫驰 → 下游客户”。

### Step 9 - 收尾总结

**口播**

“本次演示完成了从材料接收、GPT 深度分析、人工确认、正式知识沉淀，到公司、行业和企业关系洞察的闭环。飞书渠道接入和图片名单 OCR 仍是明确阻塞项，平台内部研究闭环不依赖模拟结果。”

**预期结果**

- 现场展示与实际状态一致。
- 验收记录包含通过项、阻塞项、截图、任务 ID、公司 ID 和确认记录。
