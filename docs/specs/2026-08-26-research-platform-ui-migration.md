# 研究平台能力接入现有 UI：第一阶段规格

## 目标

保留当前工作台的页面结构和样式，把已验证的研究平台业务内核接入当前仓库。第一阶段只打通“上传材料—持久任务—会话查看—重启恢复”的纵向链路。

## 已确认决策

1. 第一阶段接受单用户业务模型。
2. 第一阶段沿用研究平台内核的 SQLite 持久化。
3. RBAC、PostgreSQL、Redis/BullMQ、MinIO/S3 等生产能力后续再接。

## 必须实现

- 当前工作台上传材料时，只写入研究平台业务内核，不同时写入旧 `Store`。
- `POST /api/v1/documents` 接收文件并立即返回持久化的对话与任务。
- `GET /api/v1/conversations` 返回可在工作台会话栏展示的持久对话。
- `GET /api/v1/conversations/:conversationId` 返回真实任务步骤、分析结果和候选数量。
- 后台 worker 异步推进 `TaskStep`；服务重启后仍能读取之前的对话和任务状态。
- 当前工作台通过独立 typed client 和 view-model 使用 v1 DTO，不让展示组件直接依赖服务端模块。
- 打开持久对话时展示真实文件名、解析步骤、候选数量和任务状态；未完成任务自动刷新。

## 本阶段不做

- 不迁移待确认、公司详情、公司名单、全局搜索和管理后台的完整能力。
- 不接真实 OpenCode、Exa 或飞书 BotMux 运行时；服务端先使用确定性分析适配器。
- 不宣称多用户权限隔离、生产数据库或外部队列已经接入。
- 不重做当前 JSX 布局和 CSS。

## 公共测试接缝

- HTTP：只通过 `/api/v1/documents` 和 `/api/v1/conversations*` 观察行为，不读取 SQLite 表。
- 浏览器：通过 `ResearchPlatformClient`、工作台会话栏和任务轨道观察行为，不断言 React 内部状态。

## 验收

1. 上传 TXT 材料后返回 `201`，并生成包含持久步骤的对话。
2. worker 推进后，对话进入完成或待确认终态，并保留真实步骤状态。
3. 关闭并重新打开同一 SQLite 数据目录后，对话仍可通过 HTTP 读取。
4. 工作台会话栏显示持久对话；点击后显示真实材料名、解析步骤和候选数量。
5. 测试、TypeScript 检查和生产前端构建通过。
