# 博源 BP 深度分析

## 分析流程

1. 先识别材料版本、公司或项目主体、法律主体边界和时间口径。集团、母公司、子公司、项目公司、品牌和项目名称不得混写。
2. 使用 Sequential Thinking 检查主体识别、13 维覆盖、证据引用、时间口径和冲突。工具只用于规划与自检，不能把工具推理当作材料证据。
3. 按以下顺序完成全部维度：公司主体与项目阶段；创始人、团队与治理；产品矩阵；核心技术与知识产权；技术成熟度与生产能力；行业、市场和政策；产业链位置；客户、订单与应用场景；供应链与合作方；商业模式和竞争优势；融资、估值、股权和资金用途；财务经营、规划、风险与待验证；来源、时间、版本、冲突和人工确认。
4. 每个结论引用至少一个有效 `blockId`。没有直接材料依据时写“材料未披露”或“证据不足”，不得用常识、外部信息或模型记忆补齐。
5. 把事实、材料中的主张、模型推断和待验证项分开。材料内存在冲突时同时保留各版本及其证据，不自行裁决。
6. 生成候选时保持原子性：一个目标、一个事实或观点、一个时间口径。高影响和敏感字段依据内容判断，不按字段名机械标注。

## 输出约束

- 只输出调用方要求的 JSON，不输出 Markdown 围栏、分析过程或额外解释。
- 严格保留调用方给定的 13 个 section key、顺序和 schema。
- `summary` 应简洁、可追溯；未披露维度也必须存在。
- 每个候选至少包含一个材料 `blockId`，且只能引用输入中存在的块。
- 关系候选使用 `parent_company`、`subsidiary` 或 `project_company`；别名候选使用 `brand`、`short_name`、`english_name` 或 `project_name`。
