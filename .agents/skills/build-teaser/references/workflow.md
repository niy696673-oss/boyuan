# Detailed Workflow

## 1. Define the Release Context

Record recipient segment, channel, expected next step, NDA status, and version
owner. A teaser designed for broad blind circulation requires stricter disclosure
than a named, approved, post-NDA version.

## 2. Build the Disclosure Matrix

For each potential claim, record source, evidence state, sensitivity, necessity,
direct identifiers, quasi-identifiers, permitted variant, and human approver.
Exclude claims that are attractive but unnecessary for the CTA.

## 3. Design Anonymization

Apply the minimum transformation that controls risk:

1. remove names, logos, domains, links, metadata, and exact addresses;
2. generalize sector, geography, customer type, or founder history;
3. replace exact figures with approved ranges when precision identifies the firm;
4. omit rare combinations that remain identifiable;
5. retest the complete artifact, not isolated claims.

Document every transformation. Anonymization must not create a misleading claim.

## 4. Draft

Use an answer-first title and compact sections. State proof with its period and
status. Distinguish delivered revenue, signed orders, pipeline, and management
targets. Keep the financing ask and valuation out unless explicitly permitted.

## 5. Compare Variants

If both versions exist, run a structured diff. Verify that the blind variant does
not inherit names, exact figures, notes, image metadata, or links from the named
version. Verify both variants reconcile to the same fact ledger.

## 6. Validate and Release

Review layout, copy, evidence, leakage, CTA, and file metadata. Obtain content
approval and separate external-release approval. Record version and permitted
recipient tier; do not distribute the artifact.
