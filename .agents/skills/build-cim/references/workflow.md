# Detailed Workflow

## 1. Establish the Production Record

Create a controlled index of source files, versions, owners, dates, confidentiality,
and permitted uses. Establish one as-of date and one defined-term list. Record
which workstream owns each section and claim type.

## 2. Build the Claim Matrix

Normalize material claims with source ID, exact location, period, unit, evidence
state, voice type, disclosure tier, and reviewer. Expose conflicts before drafting.
Do not allow a later working file to silently override an official source.

## 3. Approve the Architecture

Select only relevant modules:

- transaction overview and financing plan;
- company, history, structure, and governance;
- problem, product, technology, IP, and roadmap;
- industry, market, competition, and strategy;
- customers, sales, business model, operations, and supply chain;
- team, organization, incentives, and hiring plan;
- historical financials, KPIs, forecast, and sensitivities;
- capitalization, proceeds, milestones, risks, and appendices.

The architecture is not a diligence conclusion. It organizes company-side
information for controlled investor review.

## 4. Draft by Voice

Draft management representations with clear attribution. Identify FA analysis and
its method. Cite third-party sources. Link calculations to inputs. Keep open
diligence items visibly unresolved. Place qualifications adjacent to claims.

## 5. Workstream Review

Run parallel but explicit reviews: management/FA positioning; finance/accounting;
legal and distribution; technical/commercial; confidentiality and data. Log
comments, dispositions, approver, and version.

## 6. Produce and Validate

Generate the native artifact only with validated document capability. Render and
inspect contents, pagination, tables, charts, notes, cross-references, source
markers, and restricted appendices. Compare the final artifact to the approved
claim matrix before release approval.
